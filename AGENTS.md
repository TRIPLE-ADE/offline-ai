# LearnGuide Repository Guide

## Required Expo reference

This project uses Expo SDK 57. Before changing Expo, React Native, routing,
native configuration, or platform code, read the exact versioned documentation:

https://docs.expo.dev/versions/v57.0.0/

Do not rely on older Expo conventions.

## Product

LearnGuide is a private, local-first study coach. A learner imports a TXT or
text-based PDF, and the app processes it on-device into:

- source passages and embeddings;
- an ordered topic roadmap;
- cited lessons;
- five-question knowledge checks;
- deterministic next-study recommendations;
- cited chat scoped to the selected material.

The core promise is: import material, understand it, test yourself, and know
what to study next without an internet connection.

Brand language:

- App name: LearnGuide
- Tagline: Your offline study guide.
- Store title: LearnGuide: Study Offline
- Product description: Learn from your own materials, privately and offline.

The app is a guided study product, not a general chatbot. Chat always belongs
to a material and may additionally be scoped to a topic.

Onboarding completion, offline-model installation, and material import are
independent states. Learners may finish onboarding and enter Home without a
model or material. Model-dependent actions should offer the optional download,
and source-dependent actions should guide the learner to import a PDF or TXT.
After onboarding, model download and material import are presented through
native `@expo/ui` bottom sheets rather than sending the learner back through
setup routes. Use native bottom sheets for confirmations and actionable prompts.
Use Sonner Native toasts only for passive success, error, warning, and
informational messages; do not introduce new React Native `Alert` flows.

## Product rules

- Generated lessons, quizzes, and chat answers must be grounded in stored
  source passages.
- Never invent page numbers. Use a real page, stored section title, or source
  passage ordinal.
- Refuse low-evidence questions instead of answering from unsupported model
  knowledge.
- Validate structured model output with Zod before persisting or displaying it.
- Keep deterministic fallbacks for roadmap generation, quiz scoring, and
  next-action recommendations.
- Persist roadmaps, lessons, assessments, attempts, progress, and chat so they
  survive restarts.
- Keep honest UI states for model installation, download, verification,
  material preparation, generation, interruption, retry, and offline readiness.

Current scope excludes OCR/scanned PDFs, cloud sync, accounts, analytics,
multi-material courses, and calendar planning.

## Architecture

- Expo Router owns navigation under `src/app`.
- React Native ExecuTorch runs local generation and embedding models.
- Expo SQLite owns relational product data, migrations, materials, chunks,
  learning artifacts, progress, and chat records.
- OP-SQLite/LibSQL owns the embedding/vector index. Do not merge its
  responsibility with Expo SQLite.
- `plugins/with-expo-sqlite-header-isolation.js` prevents the two native SQLite
  integrations from colliding on iOS.
- `vendor/react-native-pdfium` is a required local native dependency for
  selectable-text PDF extraction.
- This app requires a development build and does not run in Expo Go.

Primary navigation is Home, Study, Progress, and Settings. Setup is outside
the tabs. Material, topic, assessment, and material-chat routes are nested
under their owning tab.

## Toolchain

- Node.js 24
- pnpm 11
- Expo SDK 57 / React Native 0.86
- iOS deployment target 17
- Java 17 for Android

Useful commands:

```sh
pnpm install --frozen-lockfile
pnpm verify
pnpm prebuild
pnpm start:dev-client
pnpm ios
pnpm android
```

`ios/` and `android/` are generated by Expo prebuild and are intentionally
ignored. Do not make durable changes directly inside them.

## Repository hygiene

- Keep durable product knowledge in this file rather than adding planning or
  handoff Markdown files.
- Do not commit screenshots, visual experiments, generated reports, temporary
  scripts, native build output, caches, Pods, or packaged vendor archives.
- Keep actual automated tests under `src/**/__tests__`.
- Keep `fixtures/demo` because the material-processing tests use it.
- Production app icons and splash assets live in `assets/images`; the iOS 26
  icon lives in `assets/expo.icon`.
- When changing behavior, run the smallest relevant test first and finish with
  `pnpm verify`.
